## 2026-07-19 — Update: theme visual-fidelity reassessment (Cobus)

- **Intent:** Update (complete reassessment). Trigger: the built `ink-foundation` theme on staging (https://nuwe-ink.local/) does not visually resemble the Lovable design (https://id-preview--f37d6144-97e8-4535-9391-4ddb3b3a7db1.lovable.app/). Screenshots: `docs/theme-redevelopment/design-lovable.png` (intended) vs `design-staging.png` (actual). Companion diagnosis already drafted at `docs/theme-fidelity-rework-plan.md` (this session = its Phase 1).
- **Reassessment findings (confirmed by code recon of `wp-content/themes/ink-foundation/` + `ink-core`):**
  - **Not** broken CSS, **not** token drift. `theme.json` tokens are an exact match to DESIGN.md / the handoff (palette, Lora/Inter, spacing s-4..s-96, content 768 / wide 1400). Fonts + colors apply.
  - The **composition layer** was built at low fidelity. Home = single-column static placeholder patterns; the rich mockup layouts were never expressed.
  - Home-page gaps: (1) no `styles.elements.button` → buttons fall to core defaults (pill + wrong colors); (2) no plus-pattern background texture; (3) hero heading capped at `3xl=2rem`, no two-tone highlight; (4) hero is single-column, not the two-column split with a weekly-challenge side card; (5) no badge pill, no stats row (12K/48K/150K); (6) featured grid = 3 hardcoded placeholder cards (no dynamic data, no hover-lift), not the asymmetric editorial grid; (7) `ink/wenner-kollig` + `ink/borg-strook` render empty (no `ink_home_featured_winner` provider; no active sponsor); (8) header `Begin skryf` is a plain nav-link, not the terracotta CTA button.
  - No enqueued/compiled home CSS; the 7KB `styles.css` string in theme.json targets only `ink-core` reading/profile widgets.
- **Root cause (this is the key retro lesson):** the theme was built **without a concrete visual-fidelity contract.** `[ASSUMPTION #7]` (per-component appearance "lifted from Lovable .tsx at theme build") was never executed; the 2026-06-16 decision to render **no home mocks** (relying on the Lovable mockup as the authoritative reference) meant no acceptance-criteria-level spec ever existed. The build honored the concrete tokens and skipped the un-pinned composition. Unit tests read theme files by path, so no visual regression was ever caught.
- **Decisions (Cobus, 2026-07-19):**
  - **Deliverable:** a focused **theme visual-fidelity spec** (every gap → acceptance criteria + exact measured values + theme.json/block-style targets) **AND** fold the now-resolved `[ASSUMPTION]`s (esp. #7 per-component visual specs, #6 breakpoints) back into DESIGN.md (Components) + EXPERIENCE.md (Responsive & Platform / Component Patterns).
  - **Precision:** **exact values read from the `ink-lovable` source** (`/Users/cobus/Development/ink-lovable`, HEAD `5618f39` = last-synced handoff commit) — resolve Tailwind → concrete px/rem/weight/radius/gap/breakpoint. Extraction agent dispatched.
  - **Scope for the spec:** home page (Tuisblad) is the anchor; primitives (buttons, cards, badges) are shared and specced once for reuse across surfaces.
- **This resolves/closes:** `[ASSUMPTION #7]` (per-component visual tokens) and `[ASSUMPTION #6]` (breakpoints) — both to be pinned to concrete Lovable-sourced values.
