4 lenses

Accept with fixes — the spec is sound; the gaps cluster in three fixable seams, not in the pixel work. The fidelity lens spot-checked ~70 discrete values against the ink-lovable source and found them overwhelmingly correct; every "current gap" claim matched the actual theme code; and §11's dynamic-data honesty holds up against ink-core. The rubric confirms the contract is source-extractable and internally disciplined. The spec is a trustworthy build contract — but not yet buildable as written in three places:

  1. Token layer: the winner card depends on goud/brons/silwer tokens that exist in DESIGN.md frontmatter but were never added to theme.json; the spec wrongly states goud is present. (Convergent: rubric + fidelity, HIGH.)
  2. Cross-layer coupling: the winner card, current-uitdaging card, featured stream, and stats row need ink-core data/markup; the winner card needs an ink/wenner-kollig markup upgrade (Epic 12A), not just theme CSS.
  3. Mechanism friction: button size can't be a block style, buttons need an icon system the theme lacks, and core/columns won't hit the 1024/768 splits. All buildable — but the naive path walls.

Accessibility adds one critical legibility breach (gold-on-gold winner eyebrow ≈ 1.8:1) plus floor-completeness gaps (focus states, reduced-motion scope, alt-text scope, several sub-4.5:1 pairs). None of this invalidates the spec — it's a strong draft that needs one revision pass before promotion to final and Epic 19 build.

WP/FSE buildability review

review-buildability.md · buildable with friction · 0c/3h/8m/5l

Nothing infeasible on WP 7.0+; the spec is WP-aware (routes data to ink-core, correct enqueue + token discipline). But four mechanisms wall if a story assumes the naive path, and two are cross-layer (ink-core), not pure theme.

high

Winner card visual coupled to ink-core block output

spec §5 vs FeaturedWinners::toHtml()
The block emits a flat <h2>+<ul>; theme CSS can't invent the avatar/quote/crown DOM.
Fix: upgrade the ink-core block markup (Epic 12A) behind its existing seam; theme supplies token styling only.
high

Buttons need icons; theme has no icon system

spec §2/§3/§5/§8/§9
Zero inline SVG in patterns; core/button has no icon support.
Fix: establish an inline-SVG convention in 19-1 (hand-placed in locked patterns; emitted by ink-core PHP in dynamic sections).
high

Button size can't be a block style

spec §0.1/§9
register_block_style is a single radio axis; size × variant can't combine. "Height" isn't a button property.
Fix: keep variant as the block style; bake size per-instance in locked patterns via spacing/typography supports.
medium

core/columns stacks at fixed ~782px, not 1024/768; asymmetric grid not achievable

spec §2/§6
The hero 1024px split, the featured 768px split, and the span-based asymmetry aren't expressible with plain columns.
Fix: use core/group Grid layout (6.3+) with columnSpan + home.css media queries.
medium

background-clip:text on a heading sub-phrase can't be an editor block style; hsl(var/a) tints not viable; no home CSS layer exists

spec §0.3 / token-note #2 / §0 note
Three mechanism corrections bundled — the accent must be an inline element; color-mix replaces hsl(var/a); §0.3-0.6 all depend on an enqueued stylesheet that doesn't exist yet.
Fix: inline .ink-text-gradient in the locked pattern (@supports fallback); standardise on color-mix + opaque fallback; enqueue versioned home.css gated to front page (correctly first in 19-1).
medium

§3 current-uitdaging + §4/§6 data need ink-core; no theme-side computation

spec §3/§4/§6/§11
huidige-uitdaging.php is static; read-time + counts must not be computed in the theme (three-layer rule).
Fix: add an ink/huidige-uitdaging dynamic block; featured via core/query or ink-core block; counts/read-time are ink-core-owned; make "no theme-side computation" explicit in ACs.
medium

Story slicing under-specifies the ink-core dependency

spec 19-1..19-5
19-3 (winner) and 19-4 (featured) can't reach "real data" ACs until the ink-core seams land; §5 needs a cross-epic 12A markup change. Run before providers → they ship no live data silently.
Fix: split each dynamic section into presentation vs data-wiring stories; make §3/§5 ink-core work explicit blockers, not parallel; land icon + color-mix conventions in 19-1.

Accessibility review

review-accessibility.md · conditional pass (NFR-5 floor) · 1c/4h/6m/3l

Judged against the NFR-5 readability floor (no formal WCAG AA claim for v1; WCAG failures flagged as info). The spec nails the headline commitment — rank is always colour + text + icon, never colour-alone — but omits several things the floor itself names.

critical

Gold eyebrow on gold-tinted winner card ≈ 1.8:1

spec §5
Gold text on a pale-gold ground is genuinely illegible — a readability-floor breach, not just a WCAG note.
Fix: let the Crown icon + tint carry the "gold moment"; set the eyebrow/rank words in text/muted-text.
high

Pale badge pill ≈ 3.6:1

spec §2 hero badge, §3 type badge
Terracotta on primary/10 fails 4.5:1; the 12px uppercase badge (small text) is most at risk.
Fix: darken the pill text or deepen the pill background.
high

Keyboard focus states unspecified for every WP target

spec §0/§1/§9
Lovable's focus-visible:ring-2 never made it into any AC; the floor requires visible focus.
Fix: add focus-ring ACs on buttons/nav/card-links.
high

prefers-reduced-motion scoped only to §0.6 "optional" animations

spec §0.5/§0.6/§3/§6/§7
Doesn't cover the mandated hover-lift or hover:scale-105.
Fix: widen the AC to disable all transforms (lift/scale/slide/fade).
high

Alt text required only for borg logos

spec §7 vs §5/§6
Author avatars and featured images uncovered.
Fix: require alt on featured images + avatars; aria-hide decorative shapes/watermarks/plus-pattern.
medium

Contrast cluster below 4.5:1

spec §5/§7/§8/§10
White on terracotta ≈ 4.0:1 (~3.1:1 on primary-light hover); muted-text on cream ≈ 4.0:1; white/80 on CTA gradient ≈ 3.4:1; sage-as-text ≈ 4.2:1.
Fix: darken muted-text on cream; raise CTA body to white/100; avoid sage/gold as body text.
medium

Heading levels unassigned; decorative not aria-hidden; count icons unlabelled; sub-44px CTAs

spec §5/§6/§8
Skip/duplicate-h1 risk; reaction-count icons carry meaning with no label; 36-40px primary CTAs under the 44px comfortable mobile target (clears WCAG 2.5.8's 24px min).
Fix: assign explicit heading order; aria-hide decorative; label counts ("342 hartjies"); ensure ~44px mobile CTAs via padding.
