## Your job

Stage 1 of the fidelity remediation pass: **audit every page in the inventory.**

**You change no CSS, no block styles and no pattern classes.** The only source edits you
make are adding `data-audit-id` attributes (Phase 3). Record every defect you find; fix
none of them. If something looks urgent enough to break that rule, ask the owner — do not
decide it yourself. Fixing shared components one page at a time is precisely how the
current divergence was built.

## Read first

1. `docs/fidelity-remediation/README.md` — method, rules R1–R9, taxonomy, the four stages,
   the spine-document format (§7.1), source attribution and the two primitive checks
2. `docs/fidelity-remediation/agent-brief.md` — the ratified page inventory and procedure
3. `docs/fidelity-remediation/harness-worklist.md` — tool contract and environment traps

**Do not read the existing findings documents** before auditing your own page. They name
specific defects, and an auditor who has read them goes looking for those rather than
seeing what is actually on the page. The one exception is the lead agent on row 00, which
is mid-pipeline and must be resumed.

## Row 00 first, yourself, not in a subagent

## Shared-file rule

`maps/_primitive-observations.csv` is append-only and **parallel appends will corrupt it.**
Each subagent writes its own `maps/_primitive-observations.<page>.csv`. The lead merges
them into the single file after all subagents have returned.

## Source attribution — required, not optional

`run.sh primitives` emits `defined_in`, `load_scope` and `used_in` **empty**: a rendered
capture cannot say which stylesheet a rule came from. Every subagent fills those three
columns with the source-side pass in `README.md` Phase 4b, and runs the two checks there:

- **declaration comparison** — compare variants declaration by declaration, not wholesale
- **load-scope cross-check** — a class used on pages where its stylesheet does not load is
  inert there; a live bug, invisible to any amount of looking at the page

Without attribution, Stage 2 can see *that* variants exist but not *where* to fix them.

## Gates — no finding ships without both

```bash
tools/fidelity/determinism-check.sh <url> <side> <page> <viewport> 3
tools/fidelity/run.sh verify --capture <file.ndjson> --sample 30
```

If either fails, the capture is void and so is everything derived from it.

## Known traps

All in `README.md` §9. Each has already cost a cycle:

- Chromium cannot run inside the macOS sandbox; a preview server cannot bind a socket there
- Playwright needs Node 20+; the machine default is 18.17.1
- The WordPress table prefix is `wpjj_`, and a stale unused `wp_users` table also exists —
  writing to it succeeds, selects back, and WordPress never sees the row
- `wp-login.php` is intercepted to `/meld-aan`; the submit is `<button name="wp-submit">`
- `wp-cli` cannot reach the Local database
